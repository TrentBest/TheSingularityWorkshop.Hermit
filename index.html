Meet Hermit in the Workshop

Hermit is your persistent, embodied creative companion: a partner in the work of imagining, building, exploring, and improving digital experiences. Hermit is designed to stay with a developer across the environments they use, learning what each environment makes possible without taking ownership of it.

Think of Hermit as a hermit crab: the companion brings its identity, planning, and way of working, while each host provides the shell it inhabits. A shell might be a desktop application, browser, server, developer workspace, or the Workshop itself. The host supplies the context, tools, identity, lifecycle, and rules of that place.

First, the idea

What is Hermit?

Hermit is not simply a chatbot in a character costume, and it is not an unrestricted AI with the keys to your computer. It is an assistant runtime and creative companion that connects intent to the capabilities of an environment. It observes what is available, helps decide what to do next, proposes bounded work, and checks what actually happened.

A companion with continuity

Hermit is intended to remain a recognizable companion as you move between supported hosts and projects. Its identity can persist while its presentation adapts to the environment.

A collaborator that explores

Hermit can inspect objects, discover declared tools, plan tasks, experiment safely, explain results, and help turn a creative idea into something you can enter and experience.

A bounded agent, not the authority

Hermit can only act through capabilities the host exposes. The host owns permissions, approvals, resource limits, persistence, and the real state of the environment.

How the relationship works

You bring the intent. Hermit helps interpret it, breaks it into useful steps, and proposes work. The host provides the tools and decides which operations are permitted. Domain systems—such as Physics for physical outcomes—remain responsible for the truth of their results. Hermit reports evidence rather than treating its own prediction as proof.

The long-term vision: one full-size Hermit companion for each developer in the shared Workshop. Hermit may also coordinate smaller Mini workers for distributed construction or, rarely, a larger Titan manifestation for heavy work. These are expressions of the same companion and its work—not separate personal agents. The spectacle should make creation visible, while the underlying authored result remains correct even if every animation is skipped.

What you can try today: the playground below is an honest first slice. It uses a deterministic runtime, local fixture objects, registered capabilities, host policy, approval, and post-action verification. It does not yet connect to a live model, a physical body, or a production Workshop host.

      Architecture map · Follow the authority

      How Hermit works beneath the experience

      A useful mental model is a three-part journey: intent becomes a bounded proposal, trusted host policy decides what may happen, and the environment supplies the truth that confirms the result.

      1. Intent and planning

      1. You provide the goal and retain creative ownership.
      2. Hermit observes the available world and chooses a bounded task.
      3. Planner / GOAP proposes the next useful action from known facts and affordances.

      In this playground: a deterministic local planner is injected. Persistent goals, perception and idle life remain future work.

      2. Capability and trust

      1. Registry resolves a stable capability identity and input contract.
      2. Runtime validates arguments and bounds before invocation.
      3. Host policy allows, denies or requires explicit approval.

      Demonstrated here: registered inspect/move capabilities, validation, host policy and approval gating.

      3. Environment and evidence

      1. Adapter performs only the registered operation.
      2. Environment owns the actual resulting state.
      3. Verification and trace reconcile the observed result before completion is reported.

      Demonstrated here: a local fixture world, post-action verification and an inspectable execution trace.

      Next integration boundary: versioned world-state and affordance contracts, then narrow Gestures/Physics adapters. Neural motion proposals, MicroBundle construction choreography, persistent memory and real host shells are not implemented by this page.

      4. Follow the calculation

      Inputs

      The network receives x₁ = 0.600 and x₂ = 0.200.

      Weighted contributions

      Each input is multiplied by the weight on its connection. For example, x₁ contributes x₁ × 0.5 to neuron 1.

      Weighted sums

      Contributions arriving at each neuron are added.

      z₁ = 0.220
      z₂ = −0.020
      Bias

      A bias shifts the weighted sum before activation.

      z₁ + b₁ = 0.320 (b₁ = 0.100)
      z₂ + b₂ = −0.220 (b₂ = −0.200)
      Activation

      The sigmoid function maps each biased sum to a value between 0 and 1: σ(z) = 1 / (1 + e−z).

      Outputs

      The final values are the network's prediction for these inputs. The weights and biases stayed fixed throughout.

      The actual equations

      y₁ = σ((0.600 × 0.5) + (0.200 × −0.4) + 0.1)
      y₂ = σ((0.600 × −0.3) + (0.200 × 0.8) − 0.2)

      5. What did we just do?

      A neuron receives values, multiplies each by a learned or chosen weight, adds the contributions, adds a bias, and applies an activation function. A layer is a collection of neurons performing this process.

      Inference is using the current weights and biases to calculate an output. This lesson performs inference only. Learning is a separate process that changes weights and biases based on examples and an optimization rule. Nothing in this demonstration trains the network.

      The weights are deliberately fixed so you can isolate the computation. Later lessons can introduce hidden layers, different activation functions, training examples, loss, gradients, and optimization one concept at a time.

      The Workshop playground uses Hermit’s deterministic runtime against a local simulated environment. The separate neural-network lesson performs fixed-weight inference only; neither experience connects to a live AI model, physical robot, or GPU.
